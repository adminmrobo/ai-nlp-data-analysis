1LLM과 서비스

대규모 언어모델(LLM) — 범용성과 창발성

개념: 수십억~수조 매개변수의 초대형 언어모델특징: 범용성 · 창발성 · 좁은 AI → 넓은 AI · 도구 → 동반자

LLM(대규모 언어모델)은 수십억에서 수조 개의 매개변수를 가진 초대형 언어모델이에요. 교안은 GPT-3/4, Claude, PaLM을 대표 예로 들고, 두 특징을 강조해요. 하나의 모델이 번역·요약·질의응답·코딩을 하는 범용성, 훈련에서 명시적으로 배우지 않은 능력이 크기가 커지며 나타나는 창발성이에요.

이 칸에서 가져갈 한 가지

LLM은 하나의 모델로 여러 일을 하는 "넓은 AI"이고, 커지면서 새 능력이 나타난다. 하지만 학습 시점 이후 정보와 우리 회사 데이터는 모른다.

왜 이 방법을 쓰나

문제 상황

팀마다 번역기, 요약기, 분류기, 챗봇을 따로 사서 쓰고 있어요. 관리할 도구가 너무 많아요.

앞 방법의 한계

예전 AI는 작업마다 따로 만든 "좁은 AI"였어요. 번역 모델은 요약을 못 하고, 분류 모델은 답장을 못 써요.

해법

LLM 하나에 지시문으로 여러 일을 시켜요(범용성). 필요하면 특정 도메인에 맞게 미세조정해요.

쉽게 말하면 공구마다 따로 사던 것에서, 칼·드라이버·가위가 다 들어 있는 만능 공구를 쓰는 것으로 바뀐 거예요. 그래도 정밀 작업엔 전용 공구가 나을 때가 있죠.

일상으로 치면

만능 공구 하나면 웬만한 일은 다 해요. 다만 전문 작업에는 전용 공구나 숙련자의 손이 필요하죠.

자연어 처리로는

교안의 LLM 서비스:
① GPT-3(1,750억 매개변수)
② GPT-4(크기 비공개, 교안은 "1조 이상 추정")
③ Claude(교안 표기: 헌법적 AI 접근, 긴 문맥 100K+ 토큰)
④ PaLM(5,400억, Pathways 기반, 다국어·추론). 패러다임 변화: 전문가 시스템에서 범용 지능으로, 도구에서 동반자로(지식 작업자의 생산성 향상, 새로운 인간-AI 협업).

실험 — LLM의 특징 — 이 상황에선 무엇이 쓰일까

자세한 풀이 — LLM의 개념과 적용(교안) (펼쳐 보기)
  1. LLM: 수십억~수조 매개변수의 초대형 언어모델. GPT-3/4, Claude, PaLM 등.
  2. 핵심 특징: 범용성(여러 작업, 도메인 미세조정), 창발성(크기가 커지며 새 능력 출현).
  3. 패러다임 변화: 좁은 AI → 넓은 AI, 도구 → 동반자.
  4. 적용 개념: 도메인 특화 모델, 미세조정, 벡터 데이터베이스, RAG, 비즈니스 문서 생성·문서 분석 시스템.

이 칸의 한계 · 범용 LLM은 전문 분야(의료·법률·금융)의 용어와 추론에 약할 수 있어요. 도메인에 맞게 단계적으로 미세조정하는 법이 다음 칸이에요.

업무에 쓸 때 알아 둘 것 (펼쳐 보기)

데이터 분석으로 치면

LLM 도입 범위를 정할 때 "학습 데이터에 없는 정보(사내·최신)가 필요한 일"을 따로 표시하면 RAG가 필요한 곳이 보여요.

창발적 능력은 늘 재현되지 않아요. 중요한 업무는 평가를 거쳐요.

2도메인 특화

의료·법률·금융에 맞추기 — 도메인 특화 모델과 점진적 미세조정

모델: 의료 · 법률 · 금융 특화 LLM전략: 도메인 적응 → 태스크별 미세조정 → 품질 평가

범용 LLM은 넓게 알지만 전문 분야의 용어와 추론에는 얕을 수 있어요. ① 교안은 의료(논문·진료 기록)
② 법률(판례·법령·계약서)
③ 금융(재무 보고서·시장 분석) 데이터로 특화한 모델을 소개하고
④ 한 번에 맞추지 말고 점진적으로 미세조정하라고 해요. 먼저 그 분야의 대량 텍스트로 기본 이해력을 쌓고(도메인 적응), 그다음 특정 작업에 맞춰요(태스크별 미세조정).

이 칸에서 가져갈 한 가지

도메인 특화는 두 계단이다. ① 그 분야 글을 많이 읽혀 말귀를 트이게 하고(도메인 적응) ② 할 일을 가르친다(태스크별 미세조정). 그리고 품질을 계속 재고 고친다.

왜 이 방법을 쓰나

문제 상황

보험사가 상담 기록 분류에 범용 LLM을 썼더니 "면책", "갱신형" 같은 용어를 일상적인 뜻으로 잘못 이해해요.

앞 방법의 한계

라벨 데이터 몇백 건으로 곧장 분류만 가르치면, 모델이 분야의 용어와 말투를 모르는 채로 겉모양만 외워요.

해법

먼저 약관·상담 기록 같은 대량의 분야 텍스트로 도메인 적응을 하고, 그다음 라벨 데이터로 분류 작업을 미세조정하고, 평가하며 고쳐요.

쉽게 말하면 외국 병원에 간 통역사가 먼저 의학 용어집을 공부하고(적응), 그다음 진료 통역을 연습하는(작업) 순서예요.

일상으로 치면

일반 통역사가 바로 의료 통역을 하면 용어에서 막혀요. 의학 자료를 먼저 읽고 진료 상황을 연습하면 전문 통역사가 되죠.

자연어 처리로는

교안의 도메인 특화 모델: 의료(의학 논문·진료 기록·교과서
→ 진단 보조·의료 문서 요약·환자 데이터 분석), 법률(판례·법령·계약서·소송 문서
→ 법률 용어·법적 추론), 금융(재무 보고서·시장 분석·경제 뉴스
→ 투자 분석·리스크 평가·규제 준수 문서 자동화). 점진적 파인튜닝: 도메인 적응 → 태스크별 파인튜닝 → 품질 평가 및 지속적 개선.

실험 — 분야별 특화 — 어떤 데이터로 무엇을?

실험 2 — 점진적 미세조정 따라가기 — 보험 상담 분류

자세한 풀이 — 점진적 파인튜닝 전략(교안) (펼쳐 보기)
  1. 도메인 적응: 그 분야의 대량 텍스트로 기본 이해력을 쌓아요.
  2. 태스크별 파인튜닝: 특정 작업(분류·요약·추출)에 맞게 세부 조정하고 최적화해요.

  4. 함께 쓰는 것: 벡터 데이터베이스로 최신 문서를 찾아 넣는 RAG(다음 칸).

이 칸의 한계 · 미세조정은 학습 시점의 지식을 굳혀요. 이번 달에 바뀐 약관이나 새 판례는 모델에 다시 학습시키기 전까지 몰라요. 그래서 문서를 찾아 함께 넣는 RAG가 필요해요.

업무에 쓸 때 알아 둘 것 (펼쳐 보기)

데이터 분석으로 치면

전문 분야 모델은 도메인 적응 → 작업 미세조정 → 평가를 단계별 산출물로 관리하고, 전문가 검토를 마지막 단계로 둬요.

규제 분야(의료·금융·법률)는 보조 도구로만 쓰고 책임 주체를 정해요.

3LLM과 RAG

모르는 것은 찾아서 — 대규모 언어모델(LLM)과 RAG

방법: LLM · 벡터 데이터베이스 · RAG일상: 사내 규정 챗봇

LLM은 수십억~수조 개의 파라미터를 가진 언어모델이에요. 하나의 모델이 번역·요약·질의응답·코딩을 하고(범용성), 명시적으로 배우지 않은 능력이 나타나기도 해요(창발성). 하지만 학습 시점 이후의 정보와 우리 회사 데이터는 모르기 때문에, 문서를 검색해 함께 넣어 주는 RAG를 써요.

이 칸에서 가져갈 한 가지

LLM은 우리 회사 규정과 최신 정보를 모른다. 질문과 가까운 문서를 벡터 검색으로 찾아 함께 넣으면(RAG) 근거를 밝힌 답을 얻는다.

왜 이 방법을 쓰나

문제 상황

고객이 챗봇에 "반품은 며칠 안에 해야 해?"라고 물어요.

앞 방법의 한계

LLM은 일반적인 쇼핑몰 지식으로 "보통 14~30일"처럼 그럴듯하지만 우리 규정과 다른 답을 할 수 있어요(1회차의 할루시네이션).

해법

회사 문서를 벡터로 바꿔 벡터 데이터베이스에 넣고, 질문과 가장 가까운 문서를 찾아 질문과 함께 LLM에 넣어요. 답에 근거 문서를 밝히게 해요.

쉽게 말하면 처음 온 직원에게 "기억나는 대로" 답하게 하는 대신, 규정집의 해당 쪽을 펴서 보여 주고 답하게 하는 거예요.

수식이 궁금하면 펼쳐 보기 — 수학 수식을 어려워하는 조수가 대신 물어봅니다

질문과 "가까운 문서"는 어떻게 골라요?

학교 수학으로 보면 고등학교 수학의 벡터의 내적과 코사인이에요(6회차와 같은 계산).

질문 벡터 q와 문서 벡터 d의 코사인 = q·d ÷ (|q| × |d|) → 가장 큰 문서 k개를 질문과 함께 LLM에 넣음
q질문을 벡터로(이 실험은 키워드 벡터)
d문서를 벡터로. 미리 계산해 벡터 DB에 저장
k가져올 문서 수
숫자로 한 번 해 보기질문 키워드 {반품, 며칠, 이내}(3개), 반품 규정 문서 키워드 6개 중 겹치는 것 {반품, 이내} 2개코사인 = 2 ÷ (√3 × √6) = 2 ÷ 4.24 ≈ 0.47겹치는 키워드가 없는 문서(포인트 적립 등)는 0 → 반품 규정이 1위로 뽑힘

6회차의 코사인 유사도가 여기서 문서 찾기에 그대로 쓰이네요! 실제로는 키워드가 아니라 임베딩 벡터로 계산한대요.

일상으로 치면

신입 직원이 고객 질문에 기억만으로 답하면 틀릴 수 있어요. 규정집의 해당 쪽을 찾아 보여 주며 답하면 정확하고, 어디에 그렇게 쓰여 있는지도 말할 수 있죠.

자연어 처리로는

전통 데이터베이스는 키워드 정확 일치·SQL로 찾고, 벡터 데이터베이스는 임베딩 유사도로 뜻이 가까운 문서를 찾아요. RAG는 이 검색 결과로 LLM 응답을 보강하는 기법이에요. 의료·법률·금융처럼 전문 분야는 도메인 적응 → 작업별 파인튜닝 → 전문가 피드백으로 점진적으로 맞춰 가요(교안).

조수(하루)

"말귀몰"은 가상의 회사이고, 문서·답변은 예시예요. 검색은 키워드 벡터로 단순화했어요.

실험 — 회사 문서를 찾아 답하기(RAG)

실험 2 — 전통 데이터베이스 대 벡터 데이터베이스

자세한 풀이 — LLM 서비스와 활용(교안) (펼쳐 보기)
  1. LLM 예:
    ① GPT-3(1,750억 파라미터)
    ② GPT-4(크기 비공개, 교안은 "1조 이상 추정")
    ③ Claude(긴 문맥 처리)
    ④ PaLM(5,400억 파라미터) — 교안 작성 시점 기준.
  2. 핵심 특징: 범용성(하나의 모델이 여러 작업), 창발성(크기가 커지며 새 능력 출현), 좁은 AI에서 넓은 AI로, 도구에서 동반자로.
  3. 비즈니스 문서 생성: 기존 문서 수집·벡터화 → LLM 문서 생성 엔진 → 템플릿·브랜드 가이드 적용.
  4. 문서 분석: 전처리·군집화 → 벡터 검색으로 관련 문서 탐색 → LLM 요약·인사이트 → 부서별 리포트 자동화.
  5. 구축 프로세스(교안 사례): 문서 수집·전처리(형식 표준화, 정제, 메타데이터·인덱싱)
    → 임베딩 생성·클러스터링
    → 벡터 DB 저장
    → 브랜드 가이드를 반영한 생성 프롬프트 설계
    → 생성 문서 검토·품질 평가와 지속 개선.

이 칸의 한계 · RAG도 검색이 엉뚱한 문서를 가져오면 엉뚱한 답을 해요. 문서를 최신으로 관리하고, 근거를 표시하고, 중요한 답은 사람이 확인하는 운영이 함께 필요해요.
