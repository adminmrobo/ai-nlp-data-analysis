인공지능과 자연어 데이터 분석

기계가 사람의 말을 "듣는" 데서 그치지 않고 "알아듣게" 하려면, 무엇을 어떤 순서로 해야 할까?

강의 「인공지능과 자연어 데이터 분석」 8회차를 박사·조수·초파리 연구원·주판봇이 진행하고 인턴 시아·모아가 대결 심판을 맡는 해설 페이지로 다시 만들었어요. 원 강의의 학습내용 하나를 한 쪽으로 만들어, 쪽마다 칸 세 개에 직접 돌려 보는 실험, 조수가 대신 묻는 수식 풀이, 대결, 확인 퀴즈가 있고, 5회와 10회에 요약정리와 퀴즈가 있습니다. 원 강의의 5~8회차는 이 시리즈의 6~9회차예요.

처음 오신 분께 — 이 과정을 3줄로

  1. 무엇을말과 글이라는 칸 없는 데이터를 모으고(수집), 다듬고(전처리·형태소 분석), 숫자로 바꾸고(TF-IDF·Word2Vec), 순서와 문맥을 읽는 모델(RNN·LSTM·어텐션·트랜스포머)을 거쳐, 최신 언어모델(GPT·BERT·LLM)을 우리 일에 쓰는 법까지 배웁니다.
  2. 왜 중요한가회사 데이터의 큰 부분은 리뷰·문의·뉴스·보고서 같은 글이에요. 각 단계에서 무엇을 놓치면 결과가 틀어지는지 알아야 AI가 낸 결과도 판단할 수 있어요.
  3. 업무에서는고객의 소리(VOC) 분석, 리뷰 감성·키워드·주제 분석, 문의 자동 분류, 사내 검색과 문서 챗봇(RAG), 번역·요약 검수에 씁니다.

코드·수식을 몰라도 됩니다. 처음이라면 아래 한 줄 핵심 모음부터 보고, 각 회차에서는 칸마다 한 가지 핵심 → 일상 비유 → 실험만 봐도 충분해요. 수식·풀이·코드는 접어 두었어요.

각 쪽 칸 맨 위의 "이 칸에서 가져갈 한 가지"를 모았어요. 복습하거나 수업·팀 교육에서 한 장으로 띄울 때 쓰세요.

1-1 AI 모델과 자연어 분석
  1. 판단은 정보로 결론을 내리는 일, 인식은 보는 순간 대상을 알아보는 일이다. 자율주행 버스처럼 둘을 함께 쓰면 복잡한 일을 해낸다.
  2. 규칙 기반은 사람이 조건을 쓰고, 머신러닝은 과거 데이터에서 조건을 찾는다. 그래서 머신러닝에는 데이터가 필요하다.
  3. 말의 뜻은 단어 하나가 아니라 뉘앙스와 맥락이 정한다. 그래서 자연어 분석은 "좋다·나쁘다"만이 아니라 "얼마나"와 "무슨 기준으로"를 본다.
1-2 자연어 데이터의 특징
  1. 정형 데이터는 정해진 칸에 담기고 SQL·엑셀·통계로 다룬다. 자연어는 칸이 없어 자연어 분석·머신러닝이 필요하고, 분석 방법을 따로 익혀야 한다.
  2. 자연어는 칸이 없는 데이터다. 그래서 분석 전에 문장 → 어절 → 형태소로 쪼개고, 뜻이 있는 조각만 고르는 일이 먼저다.
  3. 언어는 나라·시대·유행에 따라 달라서 한 번 만든 분석 기준이 계속 맞지 않는다. 글은 단위가 없어 빈도로 바꿔야 비교·시각화할 수 있다.
1-3 비즈니스 활용 사례
  1. 뉴스·여론 분석은 "지금 사람들이 무엇에 관심을 두고 어떻게 느끼는가"를 빨리 읽어 다음 행동(제품 개선, 선거 전략, 정책 수정)을 정하는 데 쓴다.
  2. 감성 사전(규칙)은 빠르고 설명하기 쉽지만 부정어·신조어·비꼬는 말에서 틀린다. 규칙을 끝없이 더하는 대신 데이터로 배우는 쪽으로 넘어간다.
  3. LLM은 반복 작업을 빠르게 맡아 주는 "게임 체인저"지만 그럴듯한 거짓(환각)도 말한다. 사람은 해석·적용·확인을 맡는다.
2-1 분석 프로세스
  1. 이미 파일로 있으면 파일, 공식 창구가 있으면 API, 둘 다 없을 때 크롤링. 크롤링은 robots.txt와 약관부터 확인한다.
  2. 검증은 "몇 건 모았나"가 아니라 "그중 몇 건을 믿을 수 있나"를 숫자로 재는 일이다. 완전성(빠진 것), 정확성(틀린 것), 중복을 따로 본다.
  3. 다듬기 전에는 "정말·ㅋㅋ"가 1등, 다듬은 뒤에야 "배송·좋아요"가 보인다. 전처리 품질이 분석 결과를 정한다.
2-2 개발환경과 도구
  1. 라이브러리는 이미 만들어 둔 공구 세트다. 배울 때는 NLTK, 서비스로 빨리 돌릴 때는 spaCy, 글을 숫자로 바꿔 분류·군집할 때는 scikit-learn을 고른다.
  2. 통계 검정과 논문·보고서가 중요하면 R, 딥러닝과 대용량·서비스가 중요하면 파이썬. 언어는 목적이 고른다.
  3. 탐색은 노트북(Jupyter), 정리는 전문 IDE(PyCharm·RStudio), 보고는 BI 도구(Tableau·Power BI). 같은 분석도 단계마다 작업대가 다르다.
2-3 분석 모델과 방법론
  1. 자연어 처리 모델은 규칙 → 통계 → 신경망 → 트랜스포머로 발전했지만, 어떤 모델이든 먹는 것은 전처리된 데이터다.
  2. 언어 모델은 "다음에 올 단어는?"에 확률로 답한다. 통계 기반은 본 적 없는 단어 쌍에 0을 주는 희소성 문제가 있다.
  3. 단어 묶음(n)이 길수록 가능한 조합은 어휘 수의 n제곱으로 늘어 말뭉치가 따라가지 못한다. 그래서 통계 모델은 긴 문맥에 약하고, 딥러닝은 많은 데이터·계산으로 이를 푼다.
3-1 형태소 분석 개요
  1. 자연어 처리는 언어학(문법·뜻·맥락) + 컴퓨터 과학(알고리즘·자료 구조) + 통계·수학(확률·벡터) + 인공지능(머신러닝·딥러닝)이 함께 만든다.
  2. 영어는 공백이 단어 경계라 비교적 쉽지만, 한국어는 어절 ≠ 형태소라서 형태소 분석기가 필요하다.
  3. 불용어는 빼되 부정어는 지킨다. 원형 찾기는 규칙으로 자르는 어간 추출과 사전의 기본형을 찾는 표제어 추출 두 가지다.
3-2 영어 데이터 분석
  1. NLTK는 50개가 넘는 말뭉치·어휘 자원과 친절한 문서를 갖춘 "배우고 시험해 보는" 도구다. 대량·실시간 서비스에는 다른 도구를 함께 검토한다.
  2. 전처리는 원문을 "분석할 단어 목록"으로 바꾸는 공정이다. 단계마다 결과를 찍어 보며 빠진 것과 남은 것을 확인해야 한다.
  3. 품사 태깅은 "이 단어가 문장에서 무슨 일을 하나", 빈도 분석은 "어떤 단어가 몇 번 나왔나"를 알려 준다. 둘을 합치면 "많이 나온 명사"처럼 핵심어를 고를 수 있다.
3-3 한국어 데이터 분석
  1. 한국어는 한 어절에 여러 형태소가 붙고 조사·어미가 문법을 맡는다. 그래서 띄어쓰기(어절)로는 부족하고 형태소 분석이 꼭 필요하다.
  2. 속도는 Mecab > Komoran > Okt > Hannanum > Kkma. 신조어는 Okt, 세밀한 품사는 Kkma, 대용량·실시간은 Mecab, 전문 용어는 Komoran. 정확도는 문맥과 도메인에 따라 다르다.
  3. 분석기는 사전에 있는 말만 제대로 자른다. 신조어·전문용어·고유명사는 사용자 사전에 올리고, 미등록어를 모아 주기적으로 고친다.
4-1 워드 임베딩 개요
  1. 원핫은 단어 수만큼 길고 뜻을 모른다. 워드 벡터는 100~300칸으로 고정되고, 뜻이 가까운 단어를 가까이 놓는다.
  2. 원핫은 어휘가 늘수록 차원·메모리·빈칸이 함께 늘고 모든 단어가 같은 거리다. 임베딩은 차원을 300 안팎으로 고정하고, 뜻이 비슷하면 가깝게 둔다.
  3. 임베딩은 전처리 → 어휘집 → 학습 → 적용 순으로 만든다. 차원은 너무 낮으면 정보를 잃고 너무 높으면 과적합·계산 비용이 커서 보통 100~300을 쓴다.
4-2 빈도 분석과 TF-IDF
  1. 횟수(단순 빈도)는 글 길이에 끌려간다. 길이로 나눈 비율(정규화 빈도)로 봐야 짧은 글과 긴 글을 공정하게 비교할 수 있다.
  2. TF-IDF = 이 문서에서 많이 × 다른 문서에서 드물게. 모든 문서에 나오는 말은 IDF가 0에 가까워 자동으로 밀려난다.
  3. TF·IDF의 모양을 바꾸면 "반복의 힘"과 "희귀함의 힘"의 균형이 바뀐다. 어떤 변형을 썼는지 밝혀야 숫자를 비교할 수 있다.
4-3 토픽 기반 임베딩
  1. 임베딩은 빈도(세기) → 잠재 의미(압축) → 토픽(확률) → 신경망(예측) → 문맥(트랜스포머) 순으로 발전했다. 앞 방법의 한계가 다음 방법의 이유다.
  2. LDA는 문서를 여러 주제의 섞임(θ), 주제를 단어의 확률분포(φ)로 보고, 보이는 단어로 보이지 않는 θ와 φ를 거꾸로 추정한다.
  3. 토픽의 이름은 LDA가 아니라 사람이 붙인다. λ를 낮춰 "이 주제에만 많은 단어"를 함께 봐야 주제의 성격이 보인다.
6-1 Word2Vec 개요
  1. 단어의 뜻은 주변 단어(문맥)로 정해진다. 같은 자리에 들어가는 단어는 벡터 공간에서 가까워진다.
  2. 전체 어휘와 매번 비교하면 계산이 어휘 수(V)에 비례한다. 네거티브 샘플링은 정답 1 + 오답 5~20개만, 계층적 소프트맥스는 log₂V번의 예·아니오만 계산한다.
  3. 단어 사이의 관계(성별·수도·시제)는 벡터 공간의 방향이다. 같은 방향을 더하면 관계를 옮길 수 있다. 데이터의 편향도 함께 옮겨진다.
6-2 단어 벡터의 시각화
  1. 임베딩 공간에서는 거리가 뜻의 가까움, 방향이 관계를 나타낸다. 시각화는 이 군집과 방향을 눈으로 확인하는 도구다.
  2. PCA는 점들이 가장 길게 퍼진 방향(주성분)으로 그림자를 만들어 차원을 줄인다. 전체 구조는 잘 남기지만 휘어진 구조와 작은 이웃 관계는 잃는다.
  3. 전체 모양은 PCA, 이웃 군집은 t-SNE로 본다. 그리고 그림 속 가까움은 데이터가 만든 것이라 사회적 편향까지 함께 배운다.
6-3 단어의 유사도 측정
  1. 유사도는 "얼마나 비슷한가"를 0~1 사이 숫자로 말해 준다. 단어 벡터에서는 보통 0.7 이상이면 높은 유사도, 0.3 이하면 낮은 유사도로 본다.
  2. 거리는 벡터의 길이에 흔들리고, 코사인은 방향만 본다. 자주 쓰여 길어진 단어도 뜻(방향)으로 비교하려면 코사인.
  3. 데이터 모양에 맞는 자를 고른다. 벡터 방향은 코사인, 태그·키워드 집합은 자카드, 확률 분포는 KL(비대칭 주의). Word2Vec의 미등록어·다의어 문제는 FastText·BERT가 푼다.
7-1 분류·회귀와 평가
  1. 결과가 "어느 칸"이면 분류, "몇 점"이면 회귀다. 문제를 먼저 정해야 모델과 평가 지표(정확도·F1 대 MAE·RMSE·R²)가 정해진다.
  2. 로지스틱 회귀는 "단어 점수의 합"을 시그모이드로 눌러 확률로 만든다. 합이 0이면 50%, 클수록 100%에 가까워진다.
  3. 불균형 데이터에서는 정확도만 보면 속는다. 잡아야 할 것을 얼마나 잡았나(재현율)와 잡은 것 중 진짜는 얼마나(정밀도)를 함께, F1로 본다.
7-2 RNN과 LSTM
  1. 뉴런은 "가중합 → 활성화 함수" 두 동작뿐이다. 이 단순한 계산을 층층이 쌓으면 복잡한 패턴을 배운다. 활성화 함수가 없으면 아무리 쌓아도 일차함수 하나와 같다.
  2. RNN은 매 단계 기억에 같은 계수를 곱하며 넘긴다. 계수가 1보다 작으면 기억이 거듭제곱으로 사라지고(소실), 1보다 크면 폭발한다(폭주). 그래서 10~20단계 넘는 관계를 배우기 어렵다.
  3. RNN은 걸음마다 정보를 조금씩 잃어 긴 문장의 앞부분을 잊는다(기울기 소실). LSTM은 셀 상태와 세 게이트로 필요한 정보를 오래 지킨다.
7-3 Seq2Seq와 텍스트 생성
  1. Seq2Seq = 읽기(인코더) → 한 벡터로 요약(문맥 벡터) → 한 단어씩 쓰기(디코더). 앞에서 쓴 단어가 다음 단어의 입력이 된다.
  2. Seq2Seq는 문장 전체를 고정 크기 벡터 하나에 압축한다. 문장이 길수록 앞부분이 흐려지는 정보 병목이 생긴다.
  3. BLEU는 정답 번역과 1~4단어 묶음이 얼마나 겹치는지(정밀도)의 평균에, 너무 짧은 번역을 깎는 간결성 페널티를 곱한 점수다. 겹침을 보지 뜻을 보지 않는다.
8-1 Seq2Seq의 한계와 개선
  1. 자연어 모델의 발전은 "고정 벡터(Seq2Seq) → 필요할 때마다 다시 보기(어텐션) → 어텐션만으로 병렬 처리(트랜스포머) → 거대 사전학습·프롬프트"의 순서다.
  2. 매 순간 1등만 고르는 탐욕적 선택은 문장 전체로 손해일 수 있다. 빔 서치는 후보 몇 개를 남겨 문장 전체 확률이 높은 길을 찾는다.
  3. 문제마다 처방이 다르다. 정보 병목 → 어텐션, 기울기 소실 → 잔차 연결, 학습 불안정 → 층 정규화, 반복·누락 → 빔 서치 + 커버리지. 벡터 크기만 키우는 건 근본 해결이 아니다.
8-2 어텐션 메커니즘
  1. 어텐션 = Query와 각 Key의 닮음(내적) → 소프트맥스로 비율(합 1) → 그 비율로 Value를 섞은 문맥 벡터. 출력 단어마다 비율이 새로 계산된다.
  2. 어텐션 = 지금 만들 단어(Q)와 원문 단어(K)의 점수 → 소프트맥스로 가중치 → 원문 내용(V)의 가중 평균. 단어마다 다른 문맥 벡터가 생긴다.
  3. 어텐션은 번역 품질을 높일 뿐 아니라 "어느 원문 단어를 보고 이 단어를 썼는지"를 히트맵으로 보여 준다. 히트맵은 오류 진단에 쓴다.
8-3 트랜스포머
  1. 트랜스포머의 한 층 = (멀티헤드) 셀프 어텐션 → 잔차+층 정규화 → 피드포워드 → 잔차+층 정규화. 순서는 입력에 더한 위치 신호(포지셔널 인코딩)로 안다.
  2. 셀프 어텐션은 문장 안 모든 단어 쌍의 관계를 한 번에 계산한다. 그래서 병렬 계산이 되고, 먼 단어의 단서로 뜻을 정한다. 순서는 위치 정보로 더한다.
  3. 포지셔널 인코딩은 위치마다 고유한 "물결 무늬 번호표"다. 빠른 물결과 느린 물결을 섞어, 가까운 순서와 먼 순서를 모두 구별한다.
9-1 최신 언어모델 개요
  1. 규칙 기반은 정해진 문법 안에서만, 딥러닝 언어모델은 데이터에서 배운 패턴으로 문맥을 이해한다. GPT는 커질수록 Few-shot·추론·멀티모달 같은 새 능력을 보였다.
  2. GPT는 앞 문맥만 보고 다음 단어를 이어 써서 생성에 강하고, BERT는 빈칸 앞뒤를 다 보고 맞혀서 분류·이해에 강하다.
  3. 생성은 GPT, 이해·분류는 BERT 계열, 여러 작업을 한 형식으로는 T5, 글+이미지는 CLIP·DALL-E. 일의 성격이 모델을 고른다.
9-2 전이학습과 프롬프트
  1. 전이학습 = 일반 언어 능력(사전훈련)을 빌려 와 우리 일에만 조금 더 가르치기(미세조정). 대신 사전훈련 데이터의 편향도 함께 옮겨 온다.
  2. Hugging Face는 "모델 가게(Model Hub) + 같은 사용법(Transformers)"이다. 모델을 바꿔도 코드 모양이 거의 같아 실험이 빠르다.
  3. 모델을 처음부터 만들지 않는다. 사전훈련 모델을 데이터로 맞추거나(파인튜닝), 지시문으로 맞춘다(프롬프트). 형식을 정해 주면 결과를 모아 쓸 수 있다.
9-3 LLM과 RAG
  1. LLM은 하나의 모델로 여러 일을 하는 "넓은 AI"이고, 커지면서 새 능력이 나타난다. 하지만 학습 시점 이후 정보와 우리 회사 데이터는 모른다.
  2. 도메인 특화는 두 계단이다. ① 그 분야 글을 많이 읽혀 말귀를 트이게 하고(도메인 적응) ② 할 일을 가르친다(태스크별 미세조정). 그리고 품질을 계속 재고 고친다.
  3. LLM은 우리 회사 규정과 최신 정보를 모른다. 질문과 가까운 문서를 벡터 검색으로 찾아 함께 넣으면(RAG) 근거를 밝힌 답을 얻는다.
