자연어 데이터 분석 프로세스 및 모델 — 모으고, 다듬고, 확률을 매기다

리뷰 1만 건을 분석하라는 지시를 받았다. 첫날 무엇부터 해야 할까?

분석은 모델이 아니라 수집에서 시작해요. 파일·API·크롤링 중 상황에 맞는 길로 글을 모으고, 결측·중복·오류를 걸러 내고(검증), 토큰화·정제·정규화·불용어 제거로 다듬어야(전처리) 비로소 분석할 수 있어요. 마지막으로 "단어 순서에 확률을 매기는" 언어 모델이 무엇인지 봅니다.

처음 오신 분께 — 이 페이지를 3줄로

  1. 무엇을상황에 맞는 수집 방법(파일·API·크롤링)을 고르고, 수집 → 검증 → 전처리 공정으로 리뷰를 다듬고, 파이썬·R·주피터 같은 도구와 "단어 순서에 확률을 매기는" 언어 모델을 만납니다.
  2. 왜 중요한가교안은 "정확한 전처리가 분석의 성패를 좌우한다"고 강조해요. 같은 리뷰도 다듬기 전과 후에 가장 많은 단어가 완전히 달라집니다.
  3. 업무에서는VOC 수집 파이프라인 설계, 분석 환경 고르기, 경영진 보고용 시각화 도구 고르기, 언어 모델을 쓰는 검색·자동완성의 원리 이해에 씁니다.

처음이라면 이렇게 읽으세요. 칸마다 ① 가져갈 한 가지 → ② 일상으로 치면 → ③ 실험만 봐도 충분해요. 수식, 자세한 풀이, 업무 팁, 코드는 접어 두었어요(몰라도 됩니다).

왜 이 주제인가

모으는 길이 다르다

사내 파일, 실시간 API, 웹 크롤링은 장단점과 법적 주의점이 달라요.

다듬어야 보인다

중복·광고·태그·"ㅋㅋㅋ"가 섞인 채로 세면 가장 많은 단어가 "정말", "ㅋㅋ"가 돼요.

말에 확률을 매긴다

언어 모델은 "배송이 빨라요"가 "빨라요 배송이"보다 그럴듯하다는 것을 숫자로 말해요.

큰 그림 — 이 회차가 흘러가는 4단계 (펼쳐 보기)

수집 → 검증 → 전처리 → 도구 → 모델. 각 단계의 중간 결과 품질이 최종 정확도를 정해요(교안).

① 수집

파일(CSV·엑셀·텍스트), API, 크롤링·스크래핑

② 검증

결측·중복·오류 확인, 정합성, 샘플링 검증

③ 전처리

토큰화·정제 → 정규화 → 불용어 제거 → 어간·표제어 추출

④ 도구와 모델

파이썬·R, 주피터·PyCharm·RStudio, 통계 기반 대 딥러닝 언어 모델

1수집

글은 어디서 오나 — 파일 · API · 크롤링

방법: 데이터 수집 경로 선택일상: 상담 기록 · 실시간 SNS · 경쟁사 리뷰

교안은 수집 방법을 데이터의 출처·형식·양에 따라 고르라고 해요. 실시간성, 구조화 정도, 수집 비용, 그리고 법적 주의사항을 함께 따집니다.

이 칸에서 가져갈 한 가지

이미 파일로 있으면 파일, 공식 창구가 있으면 API, 둘 다 없을 때 크롤링. 크롤링은 robots.txt와 약관부터 확인한다.

왜 이 방법을 쓰나

문제 상황

분석하라는 리뷰가 사내 파일, 실시간 SNS, 다른 회사 웹 페이지에 흩어져 있어요.

앞 방법의 한계

한 가지 방법만 고집하면 갱신이 늦거나(파일), 원하는 글이 없거나(API), 법적 문제가 생겨요(크롤링).

해법

상황(어디에 있나, 얼마나 자주 새로 받아야 하나, 공식 창구가 있나)에 따라 수집 경로를 골라요.

쉽게 말하면 장보기도 냉장고(파일), 정기 배송(API), 시장 직접 가기(크롤링) 중 상황에 맞게 고르죠.

수식이 궁금하면 펼쳐 보기 — 수학 수식을 어려워하는 조수가 대신 물어봅니다

크롤링이랑 스크래핑은 같은 말 아니에요?

학교 수학으로 보면 수학의 순서도(조건에 따라 갈라지는 길)로 정리할 수 있어요.

크롤링 = 웹 페이지를 링크 따라 자동으로 돌아다니기 · 스크래핑 = 한 페이지에서 원하는 부분(리뷰 글)만 뽑기
정적 페이지HTML이 바로 오는 페이지 → BeautifulSoup·Requests·Scrapy
동적 페이지스크립트로 글이 나중에 채워짐 → Selenium·Playwright
robots.txt사이트가 "여기는 긁어 가지 마세요"를 적어 둔 파일
숫자로 한 번 해 보기상황 "경쟁사 리뷰 페이지": 공식 API 없음 → 크롤링·스크래핑갱신 주기 "매일" → 자동화가 필요하므로 파일 기반은 탈락확인 순서: robots.txt → 서비스 약관 → 저작권 → 요청 간격 설정

돌아다니는 게 크롤링, 뽑는 게 스크래핑이네요. 둘 다 "허락된 범위인지"가 먼저고요.

일상으로 치면

저녁거리는 냉장고에 있으면 꺼내고, 매주 필요하면 정기 배송을 시키고, 특별한 재료는 시장에 직접 가서 골라 와요. 남의 가게 재료를 허락 없이 가져오면 안 되죠.

자연어 처리로는

파일 기반은 접근이 쉽고 오프라인에서도 처리돼요. API는 실시간·준실시간으로 정해진 형식의 데이터를 자동으로 받아요. 크롤링·스크래핑은 공식 창구가 없을 때 웹의 글을 넓게 모으지만 robots.txt·약관·저작권을 확인하고 서버에 부담을 주지 않아야 합니다.

사내 파일이 있는데 웹을 긁는다고? 그리고 약관은 읽었어?

조수(하루)

점수는 이 페이지가 정한 설명용 가중치예요. 판단 순서를 보여 주려는 거예요.

실험 — 상황에 맞는 수집 방법 고르기

자세한 풀이 — 수집 방법 비교(교안) (펼쳐 보기)
  1. 파일 기반: CSV는 단순하고 호환성이 높아 대용량에 적합, 엑셀은 복잡한 구조·서식·수식 유지, 텍스트는 가장 기본이지만 정형화가 더 필요해요.
  2. API: 정해진 규격으로 요청하고 JSON·XML로 받아요. 뉴스 API(News API, GDELT), 공공데이터포털, 도서·학술(Google Books), 유튜브 댓글·자막 API 등이 있어요.
  3. 크롤링·스크래핑: BeautifulSoup·Scrapy·Requests(정적), Selenium·Puppeteer·Playwright(동적).
  4. 고르는 기준: 정기 수집이면 API나 크롤링, 최신성·정확성·완전성 같은 품질 요구도 함께 봐요.

이 칸의 한계 · 어떤 길로 모았든 글에는 빈 행, 같은 글의 중복, 광고, HTML 태그, "ㅋㅋㅋ" 같은 잡음이 섞여 있어요. 바로 세면 엉뚱한 결과가 나옵니다.

업무에 쓸 때 알아 둘 것 (펼쳐 보기)

현장에 옮기면

실무에서는 수집 조건(기간·키워드·플랫폼·약관 확인일)을 기록해 두어야 나중에 분석 결과를 설명할 수 있어요.

플랫폼의 API 정책과 이용 약관은 자주 바뀌어요. 이 페이지의 서비스 이름은 교안 작성 시점(2025) 기준입니다.

2검증·전처리

세기 전에 다듬기 — 검증과 전처리 공정

교안은 수집 다음에 검증(결측·중복·오류 확인)과 전처리(토큰화·정제 → 정규화 → 불용어 제거)를 두어요. 정형 데이터의 결측치·이상치 처리와 달리, 자연어는 언어학적 처리가 필요합니다.

이 칸에서 가져갈 한 가지

다듬기 전에는 "정말·ㅋㅋ"가 1등, 다듬은 뒤에야 "배송·좋아요"가 보인다. 전처리 품질이 분석 결과를 정한다.

문제 상황

리뷰 12개에서 고객이 무엇을 말하는지 가장 많은 단어로 알아보려 해요.

앞 방법의 한계

그대로 세면 같은 리뷰가 세 번 들어간 중복, 광고, "

" 같은 태그, "정말·ㅋㅋ"가 상위를 차지해요.

해법

① 검증: 빈 행·중복·광고 제거 ② 정제: 태그·주소·기호 제거 ③ 정규화: 대소문자·반복 표기 통일 ④ 토큰화 뒤 불용어 제거. 단계마다 중간 결과를 확인해요.

쉽게 말하면 채소를 씻고(검증·정제), 크기를 맞춰 썰고(정규화·토큰화), 못 먹는 꼭지를 떼어 내는(불용어) 손질이에요.

처리 후검증 뒤 남은 행
× 100%비율을 백분율로

3언어 모델

말에 확률을 매기다 — 통계 기반 언어 모델(N-gram)

방법: 바이그램 언어 모델 · 평활일상: 검색어 자동완성

교안은 언어 모델을 "주어진 문장 또는 단어 순서에 확률을 할당하는 모델"로 정의해요. 가장 단순한 것은 앞 단어 하나를 보고 다음 단어의 확률을 세는 바이그램(N-gram)입니다.

이 칸에서 가져갈 한 가지

언어 모델은 "다음에 올 단어는?"에 확률로 답한다. 통계 기반은 본 적 없는 단어 쌍에 0을 주는 희소성 문제가 있다.

왜 이 방법을 쓰나

문제 상황

검색창에 "배송이"를 치면 다음 말로 "빨라요"를 추천하고 싶어요.

앞 방법의 한계

단어를 세기만 하는 방식(앞 칸)은 순서를 버려서 "다음 말"을 예측할 수 없어요.

해법

말뭉치에서 "앞 단어 → 다음 단어" 쌍이 나온 횟수를 세고, 앞 단어가 나온 횟수로 나눠 다음 단어의 확률을 구해요.

쉽게 말하면 "배송"이 나오면 지금까지 그 뒤에 무슨 말이 몇 번 왔는지 세어 보는 거예요.

수식이 궁금하면 펼쳐 보기 — 수학 수식을 어려워하는 조수가 대신 물어봅니다

문장 전체의 확률은 어떻게 구해요?

학교 수학으로 보면 고등학교 「확률과 통계」의 조건부확률과 곱셈정리예요.

P(다음 | 지금) = 횟수(지금 다음) ÷ 횟수(지금 뒤에 무언가) · P(문장) = P(첫 단어 | 시작) × P(둘째 | 첫째) × …
횟수(지금 다음)두 단어가 이 순서로 붙어 나온 횟수
×곱셈정리: 앞에서부터 차례로 곱함
평활(+1)본 적 없는 쌍도 0이 되지 않게 분자에 1, 분모에 어휘 수를 더함
숫자로 한 번 해 보기예시 말뭉치 10문장에서 "배송" 뒤: 이 4번, 도 1번 → P(이 | 배송) = 4 ÷ 5 = 80%"이" 뒤: 빨라요 3, 늦어요 1, 좋아요 2, 싸요 1, 꼼꼼해요 1 → P(빨라요 | 이) = 3 ÷ 8 ≈ 38%"빨라요 이 배송"에는 말뭉치에 없던 쌍(시작→빨라요)이 있어 확률 = 0

곱셈이라 하나라도 0이면 전체가 0이 되는군요. 그래서 1을 더해 주는 평활이 필요했어요.
