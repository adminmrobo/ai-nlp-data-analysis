Seq2Seq의 한계와 개선 — 다음 모델을 부른 문제들

Seq2Seq는 왜 긴 문장에서 앞부분을 잊고, 같은 말을 반복할까? 무엇으로 고칠 수 있을까?

7회차의 Seq2Seq는 번역·요약·대화의 바탕이었지만, 긴 문장을 벡터 하나에 담는 한계가 있었어요. 이 쪽은 그 한계가 어떻게 어텐션·트랜스포머로 이어졌는지 흐름을 보고, 교안의 예문으로 한계를 확인한 뒤 네 가지 개선책을 증상에 짝지어 봅니다.

왜 이 주제인가

모델의 진화

번역기를 바꾸자는 회의에서 "Seq2Seq, 어텐션, 트랜스포머, GPT"가 한꺼번에 나와요. 무엇이 무엇의 개선판인지 헷갈려요.

한계와 개선

번역 모델이 단어를 하나씩 만들 때, 첫 단어 확률이 가장 높은 쪽만 따라가면 어색한 문장이 나와요.

개선책 짝 맞추기

번역 결과에 앞부분 누락, 같은 말 반복, 학습이 들쭉날쭉한 문제가 한꺼번에 보여요.

큰 그림 — 이 회차가 흘러가는 4단계 (펼쳐 보기)

모델의 진화 → 한계와 개선 → 개선책 짝 맞추기 → 다음 쪽.

① 모델의 진화

자연어 모델의 발전은 "고정 벡터(Seq2Seq) → 필요할 때마다 다시 보기(어텐션) → 어텐션만으로 병렬 처리(트랜스포머) → 거대 사전학습·프롬프트"의 순서다.

② 한계와 개선

매 순간 1등만 고르는 탐욕적 선택은 문장 전체로 손해일 수 있다. 빔 서치는 후보 몇 개를 남겨 문장 전체 확률이 높은 길을 찾는다.

③ 개선책 짝 맞추기

문제마다 처방이 다르다. 정보 병목 → 어텐션, 기울기 소실 → 잔차 연결, 학습 불안정 → 층 정규화, 반복·누락 → 빔 서치 + 커버리지. 벡터 크기만 키우는 건 근본 해결이 아니다.

④ 다음 쪽

디코더가 "어디를 얼마나 다시 볼지"는 어떻게 계산할까? Query·Key·Value는 무엇일까?

1모델의 진화

Seq2Seq에서 트랜스포머까지 — 한계가 다음 모델을 부른 이야기

흐름: Seq2Seq → 어텐션 → 트랜스포머 → 대규모 사전학습쓰임: 번역 · 요약 · 대화 · 질의응답 · 캡셔닝

교안은 7회차의 Seq2Seq에서 출발해, 그 한계가 어떻게 어텐션과 트랜스포머를 낳았는지 이야기해요. Seq2Seq는 번역·요약·대화·질의응답·이미지 캡셔닝의 바탕 모델이었지만, 긴 문장을 고정 벡터 하나에 담는 병목이 있었어요. 어텐션이 그 병목을 풀고, 트랜스포머는 어텐션만으로 모델을 다시 지었어요.

이 칸에서 가져갈 한 가지

자연어 모델의 발전은 "고정 벡터(Seq2Seq) → 필요할 때마다 다시 보기(어텐션) → 어텐션만으로 병렬 처리(트랜스포머) → 거대 사전학습·프롬프트"의 순서다.

왜 이 방법을 쓰나

문제 상황

번역기를 바꾸자는 회의에서 "Seq2Seq, 어텐션, 트랜스포머, GPT"가 한꺼번에 나와요. 무엇이 무엇의 개선판인지 헷갈려요.

앞 방법의 한계

모델 이름을 나란히 놓고 비교하면 "새것이 좋다"밖에 안 남아요. 각 모델이 앞 모델의 어떤 한계를 풀었는지 모르면 고를 이유를 설명할 수 없어요.

해법

"앞 모델의 한계 → 새 아이디어 → 남은 한계" 순서로 이어 봐요. 그러면 각 단계가 왜 나왔는지, 지금 우리 문제에 어디까지 필요한지 보여요.

쉽게 말하면 계단을 하나씩 오르며 "이 계단이 무엇을 넘으려고 생겼나"를 묻는 거예요.

일상으로 치면

편지(Seq2Seq)
→ 다시 꺼내 보는 메모(어텐션)
→ 모두가 동시에 읽는 공유 문서(트랜스포머)
→ 거대한 도서관을 미리 읽은 비서(대규모 사전학습)로 일하는 방식이 바뀌었어요.

자연어 처리로는

교안의 발전 흐름: Seq2Seq(정보 병목)
→ 어텐션 메커니즘(동적 참조)
→ 트랜스포머(셀프 어텐션, RNN 제거로 병렬 처리)
→ 대규모 사전학습 모델
→ 프롬프트 엔지니어링과 RLHF. 어텐션 기반 모델이 대규모 사전학습 모델로 이어졌어요.

박사

"다음 ▶"으로 모델의 계단을 하나씩 올라 보세요. 각 계단이 무엇을 고쳤는지 보세요.

주판봇

조수(하루)

교안의 "기술 발전의 핵심 흐름"을 단계로 옮겼어요. RLHF 설명은 9회차에서 이어져요.

실험 — 자연어 모델의 계단 오르기

자세한 풀이 — 자연어 처리 모델의 진화(교안) (펼쳐 보기)
  1. Seq2Seq: 인코더-디코더 구조로 번역·요약·대화·질의응답·이미지 캡셔닝의 바탕 모델.
  2. 한계: 고정 크기 벡터로 인한 정보 손실, 긴 문장에서 초반부 정보 희석, 순차 처리로 인한 제약.
  3. 어텐션: 인코더의 모든 숨겨진 상태를 참조해 병목 해결.
  4. 트랜스포머: 어텐션만으로 구성한 혁신적 구조, 병렬 처리로 학습 속도 향상.
  5. 그 뒤: 대규모 사전학습 모델 → 프롬프트 엔지니어링과 RLHF(9회차).

계단을 건너뛰면 비용이 크게 늘 수 있어요.

2한계와 개선

번역이 빠뜨리고 반복할 때 — Seq2Seq의 한계와 빔 서치

방법: 빔 서치 · 잔차 연결 · 층 정규화일상: 번역 후보 고르기

교안은 Seq2Seq의 한계로 정보 병목(긴 문장 앞부분 손실), 문맥 의존 오류("밤"이 night인지 chestnut인지), 반복·누락을 들어요. 개선책은 어텐션, 잔차 연결, 층 정규화, 그리고 여러 후보를 함께 고려하는 빔 서치예요.

이 칸에서 가져갈 한 가지

매 순간 1등만 고르는 탐욕적 선택은 문장 전체로 손해일 수 있다. 빔 서치는 후보 몇 개를 남겨 문장 전체 확률이 높은 길을 찾는다.

왜 이 방법을 쓰나

문제 상황

번역 모델이 단어를 하나씩 만들 때, 첫 단어 확률이 가장 높은 쪽만 따라가면 어색한 문장이 나와요.

앞 방법의 한계

탐욕적 디코딩은 지금 1등만 골라 나중에 더 좋은 길을 놓쳐요. 디코더가 같은 말을 반복하거나 중요한 말을 빠뜨리기도 해요.

해법

단계마다 문장 확률이 높은 후보를 B개 남겨 함께 키워요(빔 서치). 커버리지 장치를 더하면 반복·누락도 줄어요. 깊은 층은 잔차 연결·층 정규화로 안정시켜요.

쉽게 말하면 길 찾기에서 첫 갈림길의 최단 거리만 보지 않고, 후보 길 두세 개를 끝까지 비교하는 거예요.

수식이 궁금하면 펼쳐 보기 — 수학 수식을 어려워하는 조수가 대신 물어봅니다

문장 전체 확률은 어떻게 계산하고, 왜 빔 서치가 더 좋은 문장을 찾아요?

학교 수학으로 보면 고등학교 「확률과 통계」의 곱셈정리와 수형도예요.

P(문장) = P(1번째) × P(2번째 | 1번째) × P(3번째 | 1·2번째) · 빔 너비 B = 단계마다 남기는 후보 수
×앞에서부터 조건부확률을 차례로 곱함
B = 1탐욕적 선택: 매번 1등만
B = 2, 3후보를 여럿 남겨 비교
숫자로 한 번 해 보기탐욕적: 나는(0.45) → 커피를(0.40) → 좋아한다(0.5) = 0.45 × 0.40 × 0.5 = 0.09빔 2: 1단계에서 "저는"(0.40)도 남김 → 커피를(0.90) → 좋아해요(0.90)0.40 × 0.90 × 0.90 = 0.324 → 처음엔 2등이던 "저는"이 최종 1등

첫 단어만 보면 "나는"이 이겼는데, 끝까지 가 보니 "저는 커피를 좋아해요"가 세 배 넘게 그럴듯했어요.

일상으로 치면

처음 갈림길에서 가장 짧아 보이는 길만 고르면, 나중에 막힌 길을 만나 돌아올 수 있어요. 후보 두세 개를 끝까지 비교하면 더 좋은 길을 찾죠.

자연어 처리로는

빔 서치는 탐욕적 디코딩 대신 여러 후보를 동시에 고려해 더 나은 번역을 찾아요. 잔차 연결은 기울기 소실을 완화하고, 층 정규화는 출력 크기를 일정하게 해 학습을 안정시켜요. 그리고 근본 처방은 디코더가 인코더의 모든 은닉 상태를 참조하게 하는 어텐션이에요(교안).

박사

빔 너비를 1에서 2로 바꿔 보세요. 고른 번역과 문장 확률이 어떻게 바뀌나요?

첫 단어만 좋고 끝이 엉망이면? 문장 전체 확률을 봐.

조수(하루)

단어 확률표는 설명용 예시값이에요. 계산한 후보 수도 함께 보세요.

실험 — 탐욕적 선택 대 빔 서치

자세한 풀이 — Seq2Seq의 한계 예시(교안) (펼쳐 보기)
  1. 앞부분 손실: "어제 친구와 함께 새로 문을 연 이탈리아 레스토랑에 가서 … 정말 만족스러웠다"를 번역하면 "어제", "친구와 함께"가 빠져요.
  2. 문맥 오류: "그는 밤이 좋다고 말했다"의 "밤"이 night인지 chestnut인지 문맥 정보를 충분히 지키지 못해요.
  3. 반복·누락: 디코더가 같은 내용을 반복하거나 중요한 정보를 빠뜨려요. 긴 요약·대화에서 두드러져요.
  4. 개선: 어텐션(정보 병목), 잔차 연결(기울기 소실), 층 정규화(학습 안정), 빔 서치 + 커버리지(반복·누락).

이 칸의 한계 · 빔 서치는 "어떤 문장을 고를지"를 개선할 뿐, 원문 정보가 벡터 하나에 갇힌 문제는 그대로예요. 디코더가 원문을 다시 볼 수 있어야 해요.

업무에 쓸 때 알아 둘 것 (펼쳐 보기)

데이터 분석으로 치면

번역·요약 서비스는 보통 빔 너비 몇~열 개 정도를 쓰고, 길이 페널티로 너무 짧은 문장을 막아요.

빔을 크게 하면 계산이 늘고, 오히려 밋밋하고 짧은 문장이 뽑히기도 해요. 너비는 실험으로 정해요.

3개선책 짝 맞추기

네 가지 개선책 — 어텐션, 잔차 연결, 층 정규화, 빔 서치

개선: 어텐션 · 잔차 연결 · 층 정규화 · 빔 서치(+커버리지)효과: 병목 해소 · 동적 문맥 · 품질 향상 · 해석 가능성

교안은 Seq2Seq의 한계마다 짝이 되는 개선책을 제시해요. 정보 병목에는 어텐션, 깊은 망의 기울기 소실에는 잔차 연결, 학습 불안정에는 층 정규화, 반복·누락과 탐욕적 선택에는 빔 서치(커버리지 메커니즘과 함께)예요. 그리고 어텐션이 가져온 효과를 정리해요.

이 칸에서 가져갈 한 가지

문제마다 처방이 다르다. 정보 병목 → 어텐션, 기울기 소실 → 잔차 연결, 학습 불안정 → 층 정규화, 반복·누락 → 빔 서치 + 커버리지. 벡터 크기만 키우는 건 근본 해결이 아니다.

왜 이 방법을 쓰나

문제 상황

번역 결과에 앞부분 누락, 같은 말 반복, 학습이 들쭉날쭉한 문제가 한꺼번에 보여요.

앞 방법의 한계

"벡터 크기를 늘리면 되지 않나요?"라는 질문에 교안은 답해요. 벡터를 키우면 메모리와 계산이 기하급수적으로 늘고, 근본 해결은 어텐션이라고요.

해법

증상별로 원인을 나눠 맞는 처방을 붙여요. 어텐션은 병목, 잔차 연결은 깊이, 층 정규화는 안정성, 빔 서치는 생성 과정의 탐욕을 고쳐요.

쉽게 말하면 감기, 두통, 소화불량에 같은 약을 쓰지 않듯 증상마다 다른 처방을 붙이는 거예요.

일상으로 치면

병원에서는 열이 나면 해열제, 기침이 나면 기침약을 따로 처방해요. "센 약 하나"로 다 고치려 하면 부작용만 커지죠.

자연어 처리로는

어텐션 도입의 효과(교안): ① 정보 병목 해소 — 고정 벡터 하나에 기대지 않고 인코더의 모든 숨겨진 상태를 참조 ② 동적 컨텍스트 — 출력 단어마다 입력의 관련 부분에 집중 ③ 번역 품질 향상 — 긴 문장의 문맥·세부 정보 보존 ④ 해석 가능성 — 어떤 입력에 집중했는지 히트맵으로 확인.

박사

증상 카드 여덟 장에 알맞은 처방을 붙여 보세요.

실험 — 이 증상엔 어떤 처방?

자세한 풀이 — 개선 방향과 어텐션의 효과(교안) (펼쳐 보기)
  1. 어텐션: 고정 벡터 하나가 아니라 인코더의 모든 숨겨진 상태를 참조해 정보 병목을 해결하고, 생성 단어마다 관련 부분에 집중해요.
  2. 잔차 연결: 기울기 소실을 완화하고 깊은 네트워크의 학습을 안정시켜요.
  3. 층 정규화: 학습 안정성을 높이고 일관된 스케일의 출력을 유지해 속도를 개선해요.
  4. 빔 서치: 여러 후보를 동시에 고려해 더 나은 결과를 찾고, 커버리지 메커니즘과 함께 반복·누락을 줄여요.
  5. 현장 문답: "벡터 크기를 늘리면?" → 메모리와 계산 복잡도가 기하급수적으로 늘어요. 근본 해결은 어텐션이에요.
