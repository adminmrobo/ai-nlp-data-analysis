왜 이 주제인가

전이학습

우리 회사 상담 기록으로 문의 분류 모델을 만들고 싶은데, 라벨을 붙인 데이터가 수백 건뿐이에요.

Hugging Face

BERT로 리뷰 분류를 해 보고 싶은데, 논문의 코드를 직접 구현하고 가중치를 구하는 건 엄두가 안 나요.

전이학습·프롬프트

리뷰 1만 건을 긍정·부정·중립으로 나누려는데, 라벨 붙인 데이터는 50건뿐이에요.

큰 그림 — 이 회차가 흘러가는 4단계 (펼쳐 보기)

전이학습 → Hugging Face → 전이학습·프롬프트 → 다음 쪽.

① 전이학습

전이학습 = 일반 언어 능력(사전훈련)을 빌려 와 우리 일에만 조금 더 가르치기(미세조정). 대신 사전훈련 데이터의 편향도 함께 옮겨 온다.

② Hugging Face

Hugging Face는 "모델 가게(Model Hub) + 같은 사용법(Transformers)"이다. 모델을 바꿔도 코드 모양이 거의 같아 실험이 빠르다.

③ 전이학습·프롬프트

모델을 처음부터 만들지 않는다. 사전훈련 모델을 데이터로 맞추거나(파인튜닝), 지시문으로 맞춘다(프롬프트). 형식을 정해 주면 결과를 모아 쓸 수 있다.

④ 다음 쪽

LLM은 우리 회사 문서와 최신 정보를 모른다. 회사 문서를 찾아 함께 넣어 주면 어떨까?

1전이학습

배운 지식 옮겨 쓰기 — 사전훈련과 미세조정

방법: 전이학습(사전훈련 → 미세조정)전이: 작업 · 언어 · 도메인

전이학습은 한 작업에서 배운 지식을 관련된 다른 작업에 옮겨 쓰는 학습법이에요. 거대한 말뭉치로 언어의 일반 패턴을 먼저 배우고(사전훈련), 우리 작업의 적은 데이터로 추가 학습해 전문화해요(미세조정, 파인튜닝). 처음부터 배우는 것보다 데이터·시간·비용이 훨씬 적게 들어요.

이 칸에서 가져갈 한 가지

전이학습 = 일반 언어 능력(사전훈련)을 빌려 와 우리 일에만 조금 더 가르치기(미세조정). 대신 사전훈련 데이터의 편향도 함께 옮겨 온다.

왜 이 방법을 쓰나

문제 상황

우리 회사 상담 기록으로 문의 분류 모델을 만들고 싶은데, 라벨을 붙인 데이터가 수백 건뿐이에요.

앞 방법의 한계

처음부터 학습하면 언어 자체(문법·어휘·문맥)부터 배워야 해서 수백만 건의 데이터와 큰 계산 자원이 필요해요.

해법

BERT 같은 사전훈련 모델을 가져와, 우리 라벨 데이터 수백 건으로 분류 부분만 추가 학습해요. 언어 능력은 이미 갖고 있으니까요.

쉽게 말하면 경력직 직원을 뽑아 우리 회사 업무만 가르치는 것과, 신입에게 일과 말을 처음부터 가르치는 것의 차이예요.

일상으로 치면

요리를 잘하는 경력 요리사는 우리 가게 메뉴만 며칠 배우면 돼요. 다만 전 직장의 버릇도 함께 따라오죠.

자연어 처리로는

교안의 두 단계: ① 사전훈련 — 대규모 텍스트 코퍼스에서 언어의 일반 패턴과 지식 학습(GPT, BERT) ② 미세조정 — 특정 작업 데이터로 추가 학습해 전문화(감정 분석, 텍스트 분류). 장점: 적은 라벨 데이터로 높은 성능, 학습 시간 단축, 더 나은 일반화, 빠른 시제품. 한계: 사전훈련 데이터의 편향 전이, 목표 작업과 차이에 따른 성능 제한, 예측 불가능한 동작(블랙박스).

실험 — 이 전이는 어떤 종류?

자세한 풀이 — 전이학습의 개념, 장점, 한계(교안) (펼쳐 보기)
  1. 개념: 하나의 작업에서 학습한 지식을 다른 관련 작업에 적용하는 기계학습 기법.
  2. 두 단계: 사전훈련(대규모 코퍼스) → 미세조정(특정 작업 데이터).
  3. 장점: 소량의 라벨 데이터로 높은 성능, 훈련 시간 단축, 일반화 능력, 시제품·실험 속도 향상. 검증된 구조라 중소기업·스타트업도 최신 AI를 쓸 수 있어요.
  4. 한계: 사전훈련 데이터의 편향 전이, 목표 작업과의 차이에 따른 성능 제한, 블랙박스라 오류 원인 파악·디버깅이 어려움.

이 칸의 한계 · 전이학습을 하려면 모델을 내려받고, 토크나이저를 맞추고, 학습 코드를 짜야 해요. 이 과정을 표준화한 도구, Hugging Face가 다음 칸이에요.

2Hugging Face

Hugging Face Transformers — 모델을 빌려 쓰는 표준 창구

도구: Transformers 라이브러리 · Model Hub · 토크나이저지원: PyTorch · TensorFlow · CPU · GPU · TPU

Hugging Face는 최신 언어모델을 쉽게 쓰게 해 주는 오픈소스 생태계예요. 전 세계 연구자가 공유한 수천 개의 사전훈련 모델을 Model Hub에서 찾고, Transformers 라이브러리로 같은 방식(모델 불러오기 → 토크나이저 → 추론 → 미세조정)으로 써요. 대기업뿐 아니라 스타트업·연구소·개인도 최신 AI를 쓸 수 있게 됐어요.

이 칸에서 가져갈 한 가지

Hugging Face는 "모델 가게(Model Hub) + 같은 사용법(Transformers)"이다. 모델을 바꿔도 코드 모양이 거의 같아 실험이 빠르다.

왜 이 방법을 쓰나

문제 상황

BERT로 리뷰 분류를 해 보고 싶은데, 논문의 코드를 직접 구현하고 가중치를 구하는 건 엄두가 안 나요.

앞 방법의 한계

모델마다 코드·입력 형식·토크나이저가 제각각이면, 모델 하나 바꿀 때마다 코드를 새로 짜야 해요.

해법

Model Hub에서 모델을 고르고, 같은 인터페이스로 불러와 바로 추론하거나 미세조정해요. 토크나이저도 모델과 짝으로 받아요.

쉽게 말하면 제조사마다 다른 충전기 대신 USB-C 하나로 모든 기기를 충전하는 것과 같아요.

일상으로 치면

충전 단자가 하나로 통일되면 기기를 바꿔도 충전기를 새로 살 필요가 없어요.

자연어 처리로는

교안의 장점: 직관적이고 일관된 API(모델 로딩·토크나이저·추론·파인튜닝 표준화), 간결한 코드, 낮은 진입 장벽, 여러 언어·작업에 같은 패턴, PyTorch·TensorFlow 모두 지원(같은 코드로 백엔드 전환), CPU·GPU·TPU 환경 지원. Model Hub: 수천 개 모델 즉시 활용, 커뮤니티 기반 개선.

  1. 전이학습: 사전훈련 모델을 특정 도메인·작업에 맞게 조정.
  2. Hugging Face 생태계: 최신 언어모델을 쉽게 쓰는 오픈소스 라이브러리와 모델 허브.
  3. Transformers·토크나이저: 다양한 사전훈련 모델을 불러와 미세조정·추론하는 통합 인터페이스, 텍스트를 모델 입력으로 바꾸는 전처리 도구.
  4. 프롬프트 설계와 평가: Few-shot, Chain-of-Thought, Role Playing 등 전략과 여러 지표로 성능을 측정·조정.

이 칸의 한계 · 미세조정에는 라벨 데이터와 학습 시간이 필요해요. 모델은 그대로 두고 지시문만 잘 써서 원하는 결과를 끌어내는 방법, 프롬프트 엔지니어링이 다음 칸이에요.

같은 방법을 보여 주는 예시 코드 — 교안 코드 아님 (몰라도 됩니다)
from transformers import pipelineTransformers 라이브러리에서 파이프라인 도구를 불러와요.
clf = pipeline('sentiment-analysis', model='모델 이름')감성 분석용 모델과 토크나이저를 한 번에 불러와요.
clf('배송이 빨라요')문장을 넣으면 라벨과 확률을 돌려줘요.
3전이학습·프롬프트

빌려 쓰고 맞춰 쓰기 — 전이학습과 프롬프트 엔지니어링

방법: 전이학습(파인튜닝) · 프롬프트 엔지니어링일상: 리뷰 분류 지시문 쓰기

전이학습은 한 작업에서 배운 지식을 다른 작업에 옮기는 방법이에요. 대규모 데이터로 사전훈련한 모델을 가져와 적은 데이터로 미세조정(파인튜닝)하거나, 모델은 그대로 두고 지시문(프롬프트)을 잘 설계해 원하는 결과를 끌어내요. Hugging Face Transformers가 이 과정을 쉽게 해 줘요.

이 칸에서 가져갈 한 가지

모델을 처음부터 만들지 않는다. 사전훈련 모델을 데이터로 맞추거나(파인튜닝), 지시문으로 맞춘다(프롬프트). 형식을 정해 주면 결과를 모아 쓸 수 있다.

왜 이 방법을 쓰나

문제 상황

리뷰 1만 건을 긍정·부정·중립으로 나누려는데, 라벨 붙인 데이터는 50건뿐이에요.

앞 방법의 한계

처음부터 학습하려면 대량의 데이터와 계산이 필요해요. "이 문장을 분류해 주세요"라고만 하면 매번 다른 모양의 긴 문장이 돌아와요.

해법

사전훈련 모델을 빌려 쓰고, 프롬프트에 목적·출력 형식·예시(Few-shot)·단계(CoT)·역할·보류 규칙을 넣어요. 라벨이 많이 쌓이면 파인튜닝을 검토해요.

쉽게 말하면 여러 언어를 아는 사람이 새 언어를 더 빨리 배우는 것(전이학습), 그리고 그 사람에게 일을 맡길 때 "무엇을, 어떤 양식으로" 정확히 말해 주는 것(프롬프트)이에요.

수식이 궁금하면 펼쳐 보기 — 수학 수식을 어려워하는 조수가 대신 물어봅니다

라벨이 몇 건쯤 있어야 파인튜닝이 프롬프트보다 나아져요?

학교 수학으로 보면 고등학교 수학의 지수와 거듭제곱(음의 지수)과 함수의 그래프예요.

가정한 학습 곡선: 파인튜닝 정확도 = 0.95 − 0.5 × n^(−0.3) · Few-shot 정확도 = 0.86(일정하다고 가정)
n라벨 붙인 데이터 수
n^(−0.3)n이 커질수록 작아지는 값(데이터가 늘수록 오차가 줄어듦)
0.95이 가정에서 파인튜닝이 닿을 수 있는 최고 정확도
숫자로 한 번 해 보기n = 50: 50^(−0.3) ≈ 0.309 → 0.95 − 0.155 = 79.5% (Few-shot 86%보다 낮음)n = 5,000: 5,000^(−0.3) ≈ 0.078 → 0.95 − 0.039 = 91.1% (Few-shot보다 높음)두 곡선이 만나는 지점: 0.5 × n^(−0.3) = 0.09 → 약 n ≈ 300(이 가정에서)

데이터가 적을 땐 빌려 쓰고, 많이 쌓이면 맞춰 쓰는 거네요. 다만 숫자는 가정이라 우리 일로 직접 재 봐야겠어요.

일상으로 치면

경력 많은 신입에게 일을 맡길 때도 "알아서 해 주세요"보다 "이 양식으로, 이런 예처럼, 애매하면 표시해 주세요"라고 해야 결과를 모아 쓸 수 있어요.

자연어 처리로는

전이학습의 장점은 데이터 효율, 시간·비용 절약, 안정적 성능과 접근성이고, 한계는 사전훈련 데이터의 편향 전이, 목표 작업과의 차이, 예측하기 어려운 동작(블랙박스)이에요. 프롬프트 원칙: 목적과 출력 형식 명시, 모호함 최소화, 맥락 제공, 반복 테스트, 안전장치, 객관성 유지(교안).

자세한 풀이 — Hugging Face와 프롬프트 기법(교안) (펼쳐 보기)
  1. Hugging Face Transformers: 모델 불러오기·토크나이저·추론·파인튜닝을 같은 방식으로, PyTorch와 TensorFlow 모두 지원, Model Hub에서 공유 모델 검색.
  2. 명확한 지시: "요약해 주세요" ✗ → "다음 뉴스를 핵심 요점 3개로, 각 한 문장으로 요약" ✓.
  3. Few-shot: "'서비스가 훌륭했어요' → 긍정, '배송이 너무 늦어요' → 부정" 같은 예시를 먼저 보여 줘요.
  4. Role Playing("당신은 금융 전문가입니다…")과 Chain-of-Thought("단계별로 생각해 보세요: ① ② ③").
  5. 두 단계 학습: 사전훈련(대규모 코퍼스) → 미세조정(특정 작업 데이터). 다국어 전이, 일반 → 의료·법률·금융 도메인 적응에도 써요.

이 칸의 한계 · 프롬프트를 아무리 잘 써도 모델이 모르는 사실(우리 회사의 반품 기간, 오늘 바뀐 규정)은 만들어 낼 수 없어요. 그럴듯하게 지어낼 위험(할루시네이션)만 커져요.
